# Extraction and workspace verification — November 21, 2026

## Implemented

- Shared frontend/backend categories in `data/categories.json`; richer Aivana contract in `backend/extraction_schema.py`. The wire response is `records` plus `warnings`; backend normalization produces backward-compatible UI items carrying schema version 2, topic, skill, confidence, matching evidence, original deadline phrase, source flags, and sensitive tags. Legacy SQLite records remain readable and are not rewritten.
- Deterministic Python matching of attendee full/unique names, listed nicknames, and jerseys. Ambiguous, unknown, non-attendee, or contradictory targets stay unmatched for coach correction. Mentions must be actual bounded references, not substrings of another name/jersey.
- Python resolves explicit dates, today/tomorrow, numeric “in N days”, and weekday phrases relative to the meeting date. Weekdays normally mean the next occurrence after that date; the Level 2 follow-up below refines explicit same-day and ambiguous same-day phrases. Vague next-week/event phrases remain null with warnings; no arbitrary Monday is invented. Dates not in the source or before the meeting are cleared/flagged. Coach-selected dates are checked again on approval.
- Position-group tasks expand only to attending members; explicit whole-team actions fan out in code. Shared team feedback is stored once with its affected player IDs and appears in each relevant timeline.
- At most one corrective call for valid-shape drafts with hard content issues. If it still fails, flagged drafts and omission warnings are reviewable. HTTP/schema/auth/balance failures are not automatically retried. Truncated extractions are rejected, never partially saved.
- Editable source quotes, highlighted evidence, topic/skill dropdowns, manual additions, and low/unmatched-first review. Unresolved target/source/category issues block approval; uncertainty alone can be explicitly reviewed by the coach. New API saves require schema-v2 records.
- Raw structured output and normalized drafts stay in `extraction_runs`, separate from approved meetings. Approval verifies its snapshot, rejects repeated approval, and atomically saves records plus field-level added/edited/deleted/unchanged entries in `record_edits`. These edit logs are not an objective accuracy score.
- Sensitive record text is hidden in directory/radar previews and hidden by default in timelines/actions; explicit toggles allow review. Full notes containing sensitive items are withheld while hidden. Prep context always excludes sensitive records and is bounded to ten recent approved records. This is local UI filtering, not authentication/access control.

## Live schema failure and correction

The first upgraded live request returned 422 before extraction. Aivana’s [supported JSON Schema subset](https://developers.aivana.ai/docs/parameters#json-schema-strict) permits nullable scalar type lists but does not permit object/array type lists. The proposed nullable `action_item` object therefore could not be sent unchanged. The executable wire schema now always uses an action object, with nullable task/deadline scalar fields for an absent task. The corrected schema passed the real checks above. A regression checks supported keywords/type lists and schema size/depth. Enum values were preserved.

## Level 2 AI Assistant follow-up

Added a dedicated AI Assistant sidebar view with one selected player, optional skill/topic/meeting-date filters, action-status/action-only/search filters, and suggested prompts. Timeline entry points select the current player. The Action-board entry point carries its player, status, search, and category (including historical category names); if all players were shown, the coach must select one before asking. Dated citations expand supporting records and link to the exact meeting/record in the player's timeline. This is independent-question chat; no history or questions are persisted.

The backend retrieves only approved, non-sensitive records, including shared feedback applicable to that player. It applies filters before keyword ranking, supplies at most 12 records, and exposes matching/context counts. Full source notes and quotations are not sent to the assistant model. Live uses one structured request with at most 1200 output tokens. Each factual statement must cite supplied source IDs; invalid citations and truncated output are rejected. Citation membership is validated, not factual entailment. Coaches must still inspect supporting records. Demo returns clearly labeled saved excerpts without calling Aivana. Empty retrieval also makes no Aivana request.

Also corrected two reviewed extraction issues: a target mention must occur in its supporting quote (an unrelated mention elsewhere in the note no longer suffices), and explicit "this Friday" on a Friday resolves to that day. Bare same-day weekday phrases remain null with an ambiguity warning; "next Friday" resolves to the next occurrence. These conservative attribution checks do not prove every player/task relationship within a multi-player quotation is correct.

Matching requires identical kind, text, skill, topic, exact source quote, due date, deadline phrase, and sensitivity, with unique attending players. Completion state does not affect grouping.
