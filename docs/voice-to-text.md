# Voice to text for meeting notes

Use **Voice to text** below **The conversation** text box in Create meeting. The browser requests microphone access only when this button is clicked. Speak in English, select **Stop dictation**, and review/edit the appended text before extracting records or saving the meeting. Existing typed notes are retained; interim recognition appears separately and only finalized text enters the note. The normal review/approval and exact-source validation still apply.

This optional feature uses `SpeechRecognition` / `webkitSpeechRecognition`, not Aivana or a new backend endpoint. Browser support varies. Some browsers use an online speech service and may transmit audio there; an inline notice explains that before starting. Unsupported/insecure contexts show a disabled button and keep typing/paste available. Microphone denial, unavailable microphones, no speech, and network failures have specific messages. The app does not record or store audio. See [MDN SpeechRecognition](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition) and [stop()](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition/stop).

Finalized text dispatches the existing note input event, invalidating stale extraction/approval. Duplicate final results are ignored. The 12,000-character limit is enforced without splitting a surrogate pair. While listening, extraction/review/save clicks stop recognition and wait for final results; the coach retries the action after reviewing the text. Leaving the editor, changing meeting context/mode, hiding the page, or unloading stops capture; late callbacks cannot append text into a different meeting. No automatic microphone restart occurs.
